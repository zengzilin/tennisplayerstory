# TennisHub Deployment

Hostinger hPanel Node.js deployment settings:

```text
Framework preset: Other
Root directory: .
Build command: npm run build
Output directory: dist
Entry file: apps/api/src/main.js
Package manager: npm
Node version: 20.x
```

Required environment variables:

```env
NODE_ENV=production
WEBSITE_DOMAIN=tennisplayerstory.com

MYSQL_HOST=your-mysql-host
MYSQL_PORT=3306
MYSQL_USER=your-mysql-user
MYSQL_PASSWORD=your-mysql-password
MYSQL_DATABASE=your-mysql-database

PB_SUPERUSER_EMAIL=zilin.zeng@google.com
PB_SUPERUSER_PASSWORD=Admin123456
JWT_SECRET=replace-with-a-long-random-secret

# Daily Google Trends article generation
OPENAI_API_KEY=your-openai-api-key
OPENAI_MODEL=gpt-4o-mini
CRON_SECRET=replace-with-a-long-random-secret
GOOGLE_TRENDS_GEO=US
GOOGLE_TRENDS_HL=en-US
GOOGLE_TRENDS_TZ=-480
TREND_ARTICLE_CRON="30 9 * * *"
TREND_ARTICLE_TIMEZONE=Asia/Shanghai
TREND_ARTICLE_ALLOW_GENERAL_TRENDS=false
TREND_ARTICLE_STARTUP_CATCHUP=true
TREND_ARTICLE_STARTUP_CATCHUP_DELAY_MS=1000
TREND_ARTICLE_GENERATION_ATTEMPTS=3
TREND_ARTICLE_MAX_OUTPUT_TOKENS=8000
```

The app exposes a PocketBase-compatible API at `/hcgi/platform`, backed by MySQL. Existing frontend calls such as `pb.collection('articles').create(...)` continue to work through that compatibility layer.

Keep `TREND_ARTICLE_ALLOW_GENERAL_TRENDS=false` for scheduled publishing. When no tennis-related trend is available, the daily job records a successful skip instead of generating an unrelated article.

Daily Google Trends articles are generated by the API scheduler and published into the `articles` collection with `status: "approved"`, so they appear on the localized stories routes. Chinese remains the canonical version, while complete English, Japanese, Spanish, French, and German translations are stored in the article's `translations` object and selected by the frontend language route. The scheduler runs only when `WEBSITE_DOMAIN` is configured and the Hostinger Node.js process is running. To safely preview the online Google Trends/OpenAI flow without writing to MySQL:

```bash
curl -X POST "https://tennisplayerstory.com/hcgi/api/trend-articles/daily?dryRun=true" \
  -H "x-cron-secret: $CRON_SECRET"
```

To manually publish after deployment:

```bash
curl -X POST "https://tennisplayerstory.com/hcgi/api/trend-articles/daily" \
  -H "x-cron-secret: $CRON_SECRET"
```

Use `?force=true` only when you intentionally want to create another article for the same date.

To run the same workflow from a local machine or server shell:

```bash
npm run trend-article --prefix apps/api
```

Preview the Google Trends selection and generated Chinese draft without writing to MySQL:

```bash
npm run trend-article --prefix apps/api -- --dry-run
```

Use `npm run trend-article --prefix apps/api -- --force` only for manual testing when you intentionally want to create another article for the same date.

The scheduler performs a startup catch-up when the API process starts after the configured daily time. This covers Hostinger sleep/restart windows. The catch-up and normal cron share the same publisher lock and date-based duplicate check.

The repository also includes `.github/workflows/daily-trend-article.yml`, which calls the idempotent endpoint at 09:40 Asia/Shanghai as an external fallback. Add a GitHub Actions repository secret named `TENNIS_TREND_CRON_SECRET` with the same value as the production `CRON_SECRET`. The workflow never uses `force=true`; if the internal scheduler already published, the API returns an existing-article skip.
